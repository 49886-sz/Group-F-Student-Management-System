## 📖 What is a Product Backlog?
The Product Backlog is an ordered list of everything that might be needed in the product. It is the single source of requirements for any changes to be made to the product. The Product Owner is responsible for managing and prioritizing it.

**Prioritization Scale:**
- 🔴 **Critical** – Must have for the system to work
- 🟠 **High** – Important, adds significant value
- 🟡 **Medium** – Useful, improves experience
- 🟢 **Low** – Nice to have, can be deferred

## 🎯 Definition of Done (DoD)
A user story is considered **Done** when:
1. ✅ Code is written and committed to GitHub
2. ✅ Feature works as described in the user story
3. ✅ Tested by the developer and one teammate
4. ✅ Demonstrated to the Product Owner
5. ✅ Product Owner accepts the story in Sprint Review

---

## 🔄 Backlog Maintenance
- The Product Owner reviews the backlog **before each Sprint Planning**
- Priorities may shift based on feedback
- New stories may be added if needed
- Team estimates story points during Sprint Planning
